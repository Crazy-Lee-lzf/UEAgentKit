# 第三方参考与独立实现规则

## 基本原则

UE Agent Kit 优先参考 Epic 官方文档、公开头文件、UE API 行为和本项目测试结果。第三方仓库主要用于功能发现、架构比较、风险识别和 API 使用方式参考，不作为直接复制来源。

## 允许

- 研究公开项目提供了哪些功能。
- 对比其工作流、安全边界和模块划分。
- 记录使用到的公开 UE API。
- 根据本项目需求和官方 API 独立重新实现。
- 编写独立测试验证相同行为目标。

## 默认禁止

- 直接复制第三方源码、注释、文档段落、测试数据、提示词或资源。
- 仅替换变量名后保留原有控制流和结构。
- 将许可证不明确的源码作为生成式 AI 的实现输入。
- 未经记录把第三方代码混入普通提交。
- 复制 Unreal Engine 源码或私有项目内容进入公开仓库。

## 参考项目记录

每个重要参考项目应记录：

```text
Repository:
Reviewed Revision:
Observed License:
Reference Purpose:
Imported Source Code: No/Yes
Vendored Files: No/Yes
Independent Implementation Notes:
```

仅作为研究参考、但未随项目分发代码的第三方项目不属于发布依赖。真正随发行包分发的依赖必须记录在 `THIRD_PARTY_NOTICES.md`、`licenses/` 和 SBOM 中。

## 引入代码的例外流程

确实需要引入第三方代码时，必须单独审查并记录：

- 精确仓库和 Commit。
- 精确文件或函数。
- 许可证与版权声明。
- 修改内容。
- UE 版本适配。
- 测试结果。
- 许可证正文和 Notice 的放置位置。

许可证缺失、禁止商业使用、禁止再分发或条款不明确的内容不得引入。

## AI 使用边界

不得把以下内容提交给未经授权的外部 AI 服务：

- Unreal Engine 私有源代码。
- 公司或客户私有项目代码。
- 未公开 Blueprint 导出结果。
- 第三方无明确许可证源码。
- 访问令牌、密钥和本机私有配置。

优先提供官方 API 名称、编译错误、独立需求描述和脱敏最小复现。
